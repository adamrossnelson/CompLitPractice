macOS Command-Line Walkthrough

This is a self-paced, ~2.5 hour hands-on walkthrough. Work through the parts in order — later parts assume you’ve done the earlier ones.

Open the Terminal now before reading further: press Cmd + Space to open Spotlight, type Terminal, and hit Return. A window with a text prompt appears. That is where you’ll type every command in this guide.

What is a “prompt”?

The prompt is the short bit of text the terminal shows when it is waiting for you to type your next command. On macOS it typically ends with a % or $ character, and may include your username and the current directory before that. Whenever this guide says “at the prompt,” it means: type this command into the terminal window, then press Return.

Vocabulary as we go

Words like directory, parent, child, ~, and absolute path get introduced in short callouts the first time they appear. Don’t skip the callouts — they’re the point.

Part 1 — Finding your feet

1.1 Where am I?

Type this exactly and press Return:

pwd

pwd stands for “print working directory.” The terminal always has a current working directory — a folder it considers “where you are right now.” Every command you run acts relative to that location unless you tell it otherwise.

You’ll see something like /Users/yourname. That’s your home directory.

Folder = directory

“Folder” is the word Finder uses. “Directory” is the word programmers use. They mean exactly the same thing. This guide uses “directory” from here on.

What ~ means

~ (tilde) is a shortcut for your home directory. If your home is /Users/jsmith, then ~ and /Users/jsmith refer to the same place. ~/Desktop and /Users/jsmith/Desktop are the same folder. Every user has their own ~.

1.2 What’s in here?

ls

ls lists the contents of the current directory. You’ll see Desktop, Documents, Downloads, and so on.

1.3 The ls flag worth memorizing

Try:

ls -lhra

Memorize that combination — -lhra. It’s four flags smooshed together:

  • -l — long listing (permissions, size, modification date)
  • -h — human-readable sizes (4.0K, 1.2M instead of raw bytes)
  • -r — reverse the sort order
  • -a — show all files, including hidden ones (names starting with .)
What is a “flag”?

A flag (also sometimes called an option or a switch) is a short modifier you add after a command to change how that command behaves. Flags almost always begin with a hyphen: -l, -a, -r, -h. When several single-letter flags are combined, they are usually written together after one hyphen — so -lhra is the same as writing -l -h -r -a separately. Learning a command means, in large part, learning which flags are worth memorizing.

Hidden files

Any file or directory whose name starts with a . is hidden by default. .zshrc, .git, .DS_Store are all hidden. Plain ls won’t show them — ls -a will.

Try it: What hidden files are in your home directory?

Run ls -lhra ~ and read the leftmost column of names. You’ll likely see things like .zshrc, .zsh_history, .gitconfig, .DS_Store. These are configuration and system files — leave them alone for now, but know they exist.

1.4 Moving around: cd

cd stands for “change directory.” Try each of these, one at a time, running pwd after each so you can see where you land:

cd ~/Desktop
pwd
cd ..
pwd
cd -
pwd
cd
pwd

What each did:

  • cd ~/Desktop — go to your Desktop.
  • cd .. — go up one level to the parent directory. .. always means “the parent of where I am.”
  • cd - — jump back to the previous directory you were in. Very useful for hopping between two folders.
  • cd with no argument — go home. Same as cd ~.
What is an “argument”?

An argument is an extra word you type after a command to tell it what to act on. In cd ~/Desktop, the string ~/Desktop is the argument — it tells cd where to go. In ls -lhra ~, the flags -lhra and the path ~ are both arguments. Some commands (like pwd) take no arguments at all; some accept several; some accept optional arguments and fall back to a default when none is given (as cd falls back to sending you home).

Parent, child, sibling

Directories form a tree. If Desktop lives inside /Users/jsmith, then /Users/jsmith is the parent of Desktop, and Desktop is a child of /Users/jsmith. Two directories that share the same parent (Desktop and Downloads, for example) are siblings.

What is a “path”?

A path is the address of a file or a directory on your computer — the sequence of directory names, separated by slashes, that tells the system exactly where to find that item. /Users/jsmith/Desktop/notes.txt is a path; so is drafts/readme.txt; so is ... Almost every command that touches a file or folder takes a path as one of its arguments.

Absolute vs. relative paths
  • An absolute path starts with / (or ~, which expands to an absolute path). It works no matter where you currently are. Example: /Users/jsmith/Desktop/notes.txt.
  • A relative path does not start with /. It’s interpreted relative to your current working directory. If you’re in ~/Desktop, then notes.txt refers to ~/Desktop/notes.txt.

When a command “can’t find” a file, the #1 cause is confusing relative and absolute paths.

1.5 Tab completion — the single best trick

What is the “shell”?

The shell is the program running inside the terminal window that reads what you type, interprets your commands, and shows the results. When this guide says “the shell will complete it,” it means the program that is listening to your keystrokes. On modern macOS, the default shell is called zsh; on older Macs it was bash. The differences between shells matter to advanced users but hardly at all to beginners — for our purposes, “the shell” and “the terminal” can be used almost interchangeably.

Type cd ~/Doc and then, before pressing Return, press the Tab key. The shell will complete it to ~/Documents/ for you.

If there are multiple matches (e.g., Documents and Downloads both start with Do), the shell will beep. Press Tab twice and it lists all matches; type another letter or two to disambiguate, then Tab again.

Use Tab constantly. It prevents typos, and it’s a sanity check: if Tab won’t complete a name, that name doesn’t exist where you think it does.

1.6 Set up your practice folder

You’ll do all the rest of this walkthrough inside a dedicated practice folder so you don’t accidentally disturb anything else.

Challenge: create ~/Projects/computer-literacy and cd into it

Two commands. Try to write them yourself before revealing.

mkdir -p ~/Projects/computer-literacy
cd ~/Projects/computer-literacy

mkdir = “make directory.” The -p flag says “also create any missing parent directories” — so if ~/Projects doesn’t exist yet, it makes that too.

Confirm you’re in the right place:

pwd

You should see /Users/yourname/Projects/computer-literacy.

Part 2 — Making, moving, renaming, deleting

You’re inside ~/Projects/computer-literacy. Everything from here happens in this folder unless stated otherwise. If you ever get lost, run cd ~/Projects/computer-literacy to come home.

2.1 Create an empty file

touch notes.txt
ls

touch creates an empty file if it doesn’t exist (and updates the modification time if it does).

File extensions

The .txt at the end is a file extension. Extensions are just naming conventions — the operating system uses them as hints to guess what program should open a file. They’re not magic: notes.txt and notes.csv and notes are all just files with different names. But the convention matters, because tools (and humans) read the extension to decide what to expect. You’ll encounter .txt, .csv, .md, .qmd, .ipynb, .py, and .html in this guide.

2.2 Rename with mv

mv notes.txt readme.txt
ls

mv means “move,” but move and rename are the same operation — you’re changing the file’s path, which may involve changing its name, its location, or both.

2.3 Move into a child directory

Challenge: create a drafts/ folder and move readme.txt into it 
mkdir drafts
mv readme.txt drafts/
ls
ls drafts

After this, readme.txt should appear inside drafts/ and not in the current directory. The trailing / on drafts/ isn’t required, but it signals “this is a folder” to your future self reading the command.

2.4 Move a file from a child back to the current directory

Idea: Use your computer finder (the point and click desktop file navigator) to confirm that you’ve created the files and also that they move between directories as you perform the mv commands.

Challenge: move readme.txt from drafts/ back to where you are now 
mv drafts/readme.txt .
ls

The . is not a typo. . means “the current directory.” So mv drafts/readme.txt . reads as “move the file drafts/readme.txt into the directory .” — i.e., here.

2.5 Move a file up to the parent

Challenge: move readme.txt up to ~/Projects, then back 
mv readme.txt ..
ls
ls ..
mv ../readme.txt .
ls

.. means “the parent directory,” so mv readme.txt .. moves the file up one level. Then mv ../readme.txt . brings it back.

2.6 Copy with cp

cp readme.txt readme-backup.txt
ls

For directories, you need -r (recursive), because copying a folder means copying everything inside it too:

cp -r drafts drafts-backup
ls

2.7 Delete with rm — read this carefully

rm is permanent

There is no Trash. There is no undo. rm deletes files immediately and forever. Read every rm command twice before pressing Return, and never, ever run rm -rf / or rm -rf ~ or rm -rf * while you’re still learning.

rm readme-backup.txt
ls

For directories, rm -r:

rm -r drafts-backup
ls

Leave readme.txt and drafts/ alone — you’ll use them in Part 3.

Part 3 — Editing text with nano

nano is a beginner-friendly text editor that runs inside the terminal. Open your readme.txt:

nano readme.txt

The file opens in an editor. The bottom of the screen shows shortcuts. The ^ symbol means the Control key — so ^O means Control + O, and ^X means Control + X.

Type in these exact lines (you can copy-paste into the terminal):

Computer Literacy Practice
==========================
This is my practice readme.

TODO: add a list of my favorite CLI commands
TODO: try grep on this file later

Save the file: press Control + O, then Return to confirm the filename. Exit nano: press Control + X.

Now verify what you wrote:

cat readme.txt

cat (short for “concatenate”) prints a file’s contents to the terminal. Great for short files. Don’t cat a huge file — it will flood your terminal.

What does “concatenate” mean?

To concatenate two or more things is to join them end-to-end into a single, longer thing. The word comes from the Latin catena, meaning “chain” — so concatenation is, literally, chaining things together. In computing you’ll meet the word most often in two places: (1) here, in the name of the cat command, which was originally designed to join several files together and print the joined result; and (2) in almost every programming language, where “string concatenation” means gluing two pieces of text together (for example, joining "Hello, " and "world" to produce "Hello, world").

The TODO: lines are on purpose

You just planted two TODO markers. You’ll search for them with grep in Part 6. Real developers scatter TODO comments through their code as reminders, and being able to find them across a project is a genuinely useful skill.

Part 4 — Downloading and previewing real data

You’ll download three CSV files, then practice looking at them without opening a spreadsheet.

4.1 Make a data/ folder and go into it

mkdir data
cd data
pwd

4.2 Download files with curl

curl -O downloads a file from a URL and saves it using the filename from the URL. Run these three commands (each is one long line):

curl -O https://raw.githubusercontent.com/adamrossnelson/confident/refs/heads/main/data/complaints-bank.csv
curl -O https://raw.githubusercontent.com/adamrossnelson/confident/refs/heads/main/data/mpg_excerpt.csv
curl -O https://raw.githubusercontent.com/adamrossnelson/confident/refs/heads/main/data/confident_fictional_books.csv

4.3 See what you got

ls -lhra

Now the -h in -lhra is doing real work — you can see file sizes in KB/MB instead of raw bytes. Which of the three CSVs is largest?

4.4 Peek at contents — the right way

What is a CSV file?

CSV stands for comma-separated values. It’s the simplest, most portable format for tabular data — that is, data arranged in rows and columns, the way you’d lay it out in a spreadsheet or a printed table. Each row is one observation or record (one respondent in a survey, one transaction in a bank ledger, one book in a library catalog); each column is one variable or field (that respondent’s age, the transaction’s amount, the book’s title). Inside the file itself, each line is one row, and the values within a row are separated by commas. The very first line of a CSV is usually a header listing the column names.

CSVs are everywhere in data science because they are plain text (so any program on any system can read them), lightweight (they store nothing but the data itself — no fonts, no colors, no formulas), and language-agnostic (Python, R, Excel, and even a plain text editor can all open the same file). When you download data from a government open-data site, a research repository, or an API, it very often arrives as a CSV.

What does “portable” mean?

When programmers describe a file format, a program, or a piece of code as portable, they mean that it works well across many different systems and situations — the way a paperback book is portable in the everyday sense of “you can take it anywhere.” A portable file format opens on a Mac, a Windows PC, a Linux server, and a Chromebook, in software written by many different companies, without needing conversion. Plain-text formats such as CSV, JSON, and Markdown are among the most portable formats in existence, which is a large part of why they have endured for decades.

What is an API?

API stands for application programming interface. In broad terms, an API is a well-defined set of rules that lets one piece of software request information or services from another. For our purposes, the most common kind of API is a web API: a service somewhere on the internet that you (or a program) can send a request to, and that sends structured data back in response — very often as a CSV or JSON file. Weather services, government statistics offices, universities, and social-media platforms all publish web APIs that researchers use to gather data. You are not expected to use an API in this walkthrough; the term appears here only because CSVs are one of the most common formats that APIs return.

Do not cat complaints-bank.csv — it’s big and will fill your terminal with noise. Instead:

head confident_fictional_books.csv

head shows the first 10 lines by default. Add -n 5 to see only the first 5:

head -n 5 confident_fictional_books.csv

For scrolling through a larger file, use less:

less complaints-bank.csv

You are now “inside” less. Use arrow keys or space bar to scroll. Press q to quit. Getting stuck in less is a rite of passage — remember q.

When a program “traps” your prompt

Some commands hand control over to a program (nano, less, a running web server). Your normal shell prompt disappears until you exit the program. If you ever feel stuck: try q (for less and manual pages), Control + X (for nano), or Control + C (which sends an “interrupt” signal to most other programs).

4.5 Count rows

Why count rows from the command line?

A row count is the fastest possible answer to a basic data-science question: how many observations (records) does this dataset have? Before you open a file in Python, R, or a spreadsheet, wc -l tells you in a fraction of a second whether you’re looking at 50 rows, 50 thousand, or 50 million. That number shapes everything that comes next: whether it’s safe to load the whole file into memory, whether you should take a sample first, and whether the file actually contains what someone told you it did. Getting used to inspecting data at the shell — sizes, row counts, first few lines — before jumping into a full analysis is a habit that separates confident analysts from frustrated ones.

wc -l complaints-bank.csv

wc = “word count.” -l says “count lines.” That first line is the CSV header, so the number of data rows is one less than what wc reports.

Try it on all three CSVs at once using a wildcard:

wc -l *.csv

The * matches any characters, so *.csv matches every file in the current directory ending in .csv. Wildcards are powerful — and dangerous with rm. Be extra careful when combining * with anything destructive.

Part 5 — Redirection: saving output to a file

Very often you want to save what a command prints, rather than just look at it. That’s called redirection.

5.1 The > operator

head -n 20 complaints-bank.csv > ~/Desktop/complaints-sample.csv

Read that out loud: “Take the first 20 lines of complaints-bank.csv, and instead of printing them to the terminal, redirect them into a new file called complaints-sample.csv on my Desktop.”

Now open your Desktop in Finder (or run open ~/Desktop) — you’ll see a small CSV file there. Double-click it to open in Numbers or Excel. This is a very common real-world workflow: make a small excerpt of a big data file so you can inspect it quickly.

> silently overwrites

If ~/Desktop/complaints-sample.csv already existed, > would replace it without asking. There is no “are you sure?” prompt. If you want to append to a file instead of overwriting it, use >> (two greater-than signs).

5.2 Try >>

head -n 3 mpg_excerpt.csv >> ~/Desktop/complaints-sample.csv
cat ~/Desktop/complaints-sample.csv

You just appended a few rows of a different CSV onto the end of the sample file. (In real work you’d only append data that has the same columns — but the mechanic is worth seeing.)

Challenge: make a 50-row sample of mpg_excerpt.csv on your Desktop 
head -n 50 mpg_excerpt.csv > ~/Desktop/mpg-sample.csv

Part 6 — Searching with grep

grep searches text inside files. It’s one of the most-used commands in a working programmer’s life.

Go back up to your practice folder:

cd ~/Projects/computer-literacy
pwd

6.1 Search in a single file

You planted TODO: markers in readme.txt back in Part 3. Find them:

grep TODO readme.txt

grep prints every line in readme.txt that contains the string TODO. Add -n to include line numbers:

grep -n TODO readme.txt

6.2 Make a Python file with more TODOs

Now let’s give grep something more realistic to hunt through. Create a Python file with nano:

nano cleanup.py

Type or paste in the following (this uses only Python’s built-in features — you don’t need to install anything, and you don’t need to run it; you’re just going to search it):

# cleanup.py — a small script for tidying up a text file

import os
import sys

# TODO: accept the input filename as a command-line argument
INPUT_FILE = "notes.txt"
OUTPUT_FILE = "notes-clean.txt"


def strip_blank_lines(lines):
    """Return only the non-empty lines."""
    return [line for line in lines if line.strip() != ""]


def lowercase_all(lines):
    # TODO: preserve proper nouns instead of lowercasing everything
    return [line.lower() for line in lines]


def main():
    if not os.path.exists(INPUT_FILE):
        print(f"No such file: {INPUT_FILE}")
        sys.exit(1)

    with open(INPUT_FILE) as f:
        lines = f.readlines()

    lines = strip_blank_lines(lines)
    lines = lowercase_all(lines)

    # TODO: also remove duplicate lines before writing out
    with open(OUTPUT_FILE, "w") as f:
        f.writelines(lines)

    print(f"Wrote {len(lines)} lines to {OUTPUT_FILE}")
    # TODO: report how many blank lines were removed


if __name__ == "__main__":
    main()

Save with Control + O, Return, then exit with Control + X.

6.3 Find all TODOs in one file

grep -n TODO cleanup.py

You should see four TODO lines with their line numbers.

6.4 Find TODOs across every file in the folder

Challenge: search recursively for TODO starting at the current directory 
grep -rn TODO .
  • -r means recursive — descend into subdirectories.
  • -n adds line numbers.
  • . is the starting point (current directory).

You should see hits from both readme.txt and cleanup.py. This is how you find every leftover TODO in a project.

6.5 Case-insensitive search

grep -rni todo .

-i makes the match case-insensitive, so it would find TODO, Todo, and todo all at once.

Part 7 — Multiple terminal sessions and local web servers

Some commands take over your prompt and don’t give it back until you stop them. This is normal, and it’s why real developers usually have two or three terminal windows open at once.

7.1 Open a second terminal window

In the Terminal app, press Cmd + N for a new window (or Cmd + T for a new tab in the same window). You now have two independent shells. Each has its own current working directory.

Confirm:

  • In the new window, run pwd. It probably says /Users/yourname — a fresh shell always starts at your home directory.
  • In the old window, run pwd. It’s wherever you last cd’d to.

Two windows, two locations, one machine. Files you create in one are immediately visible from the other.

7.2 Start a mini web server

In your original terminal, make sure you’re in the practice folder, then run:

cd ~/Projects/computer-literacy
python3 -m http.server 8000

You’ll see something like Serving HTTP on :: port 8000. Your prompt is gone — Python is now running a small web server that serves the files in this folder over the network.

Open a web browser and go to http://localhost:8000. You’ll see a listing of your practice folder — click readme.txt to view it, click into data/ to see the CSVs, etc.

What is localhost?

localhost (a.k.a. 127.0.0.1) is a special network name that always means “this same computer.” When a program serves at localhost:8000, it’s only reachable from your own machine — nobody on the internet can see it. That’s why local previews are safe.

7.3 Why the second terminal matters

Your first terminal is “busy” running the web server. If you want to keep working — ls, cd, edit files — you need the second terminal window from 7.1. Try it: switch to the second window and run ls in the practice folder. It works, because that shell is independent.

7.4 Stopping the server

Switch back to the terminal running the server and press Control + C. The server stops, and your prompt returns. Control + C sends an “interrupt” signal — it’s the universal “please stop, program” keystroke.

The same pattern applies to quarto preview and jupyter lab

When you run quarto preview on a Quarto project (like this website), or jupyter lab / jupyter notebook to open notebooks, those tools also start a local web server. Same idea: the terminal becomes busy, you open a second terminal for other work, and you use Control + C to shut the server down when you’re done.

Part 8 — Three flavors of notebook

A notebook is a document that mixes prose, code, and code output (numbers, tables, plots) in one file. Three tools you are likely to meet in a graduate-level data-science setting are Jupyter Notebook, JupyterLab, and Quarto. You do not need to install or open any of them in this walkthrough; the goal of this section is to give you enough vocabulary that you will recognize each one when you meet it in a later course or on a colleague’s screen.

8.1 Jupyter Notebook (classic)

  • File extension: .ipynb
  • How you open it: run jupyter notebook in a terminal; a browser tab opens.
  • Feel: simple, one notebook per browser tab. The older interface.
  • File format under the hood: JSON. Not human-friendly to read as plain text, and hard to compare across versions.
What does “under the hood” mean?

“Under the hood” is an idiom borrowed from car mechanics. The hood of a car is the metal cover over the engine; to look “under the hood” is to see how the machine actually works, hidden from the ordinary driver. In writing about software, “under the hood” describes the internal mechanism of something — how a program actually stores its data, or how a feature is actually implemented — as opposed to the polished surface the user sees. When this guide says a .ipynb file is JSON under the hood, it means: the friendly notebook you see in your browser is, at bottom, stored on disk as a JSON document.

What is JSON?

JSON (pronounced jay-son) stands for JavaScript Object Notation. It is a plain-text format for storing structured data — data with named fields, nested lists, and hierarchies. A JSON file looks something like {"name": "Ada", "age": 36, "skills": ["math", "engineering"]}. It is designed to be read and written by programs rather than by humans, and although it is technically plain text, a large JSON file is tedious to read directly. JSON is one of the two most common formats (alongside CSV) that programs and web services use to exchange data.

What does it mean to “compare across versions”?

Writers, researchers, and programmers routinely want to answer a very specific question: what changed between the earlier version of this file and the current one? Specialized tools produce a side-by-side or line-by-line report of the differences — such a report is often called a diff, from the word difference. Files that are stored as clean plain text (a .qmd file, a Python script, a Markdown document) produce readable diffs: you can see, line by line, exactly what was added, removed, or changed. Files that are stored in complicated binary or nested formats (a Jupyter .ipynb file, a Word document, a Photoshop file) produce diffs full of noise, because a small visible change on screen can cause many invisible changes in the underlying storage.

8.2 JupyterLab

  • File extension: still .ipynb — same file format as classic Jupyter.
  • How you open it: run jupyter lab in a terminal.
  • Feel: a more modern, IDE-like layout — file browser on the left, tabs across the top, and the ability to open several notebooks and terminals side by side. The same notebook file, in a nicer environment.
  • Same version-comparison problem as classic Jupyter, because the underlying file format is identical.
What is an IDE?

IDE stands for Integrated Development Environment. It is a single application that bundles together the several tools a programmer typically needs — a text editor for writing code, a file browser for navigating a project, a terminal for running commands, a debugger for inspecting a running program, and often more — into one coordinated window. Popular IDEs you may encounter include Visual Studio Code, PyCharm, RStudio, and Xcode. JupyterLab is described as IDE-like because, although it is really a notebook interface, it borrows the multi-panel, tabbed layout that IDEs use.

8.3 Quarto notebooks

  • File extension: .qmd
  • How you open it: any text editor. To render it into a webpage or PDF, run quarto render or quarto preview in a terminal.
  • Feel: plain text — Markdown prose interleaved with code blocks. The website you are reading right now is built from .qmd files.
  • Version-comparison-friendly: because a .qmd file is plain text, comparing two versions of one is straightforward and readable.

Try it: peek at a .qmd file with commands you already know

The pages you are reading are .qmd files. If you have downloaded the source of this website into a folder called CompLitPractice, try:

cd ~/Projects/CompLitPractice
ls -lhra
head macos.qmd

Notice that a .qmd file is just readable text: ordinary Markdown, with code fences marking off the executable chunks.

What are “code fences”?

In Markdown, a code fence is a line of three backtick characters (```) that marks the beginning or end of a block of code. Anything between an opening fence and a closing fence is treated as literal code — rendered in a monospaced font, not interpreted as prose, and (in Quarto and similar tools) sometimes actually executed as a program. You can also write the language name after the opening fence, as in ```python or ```bash, so that the code is displayed with the correct syntax highlighting. Every code example in this walkthrough is written between a pair of code fences.

Common gotchas

  • rm has no undo. Read every rm twice.
  • > overwrites silently. Use >> to append.
  • ~ is different for each user. It always points at your home.
  • Relative paths depend on where you are. When something “can’t be found,” run pwd and think about it.
  • Tab-complete constantly. If Tab won’t complete a name, the thing isn’t there.
  • Case matters on servers and inside programs, even if the macOS filesystem is usually forgiving.
  • Filenames with spaces need quotes: mv "My File.txt" backup/ — or, better, avoid spaces in filenames you’ll touch from the CLI.
  • Some commands trap the prompt. Escape hatches: q (less, man), Control + X (nano), Control + C (most other running programs).

Part 10 — Check your understanding

Thirty multiple-choice questions covering everything above. Try to answer each one from memory, then click to reveal the correct answer with a short explanation.

Q1. What does pwd do?

  • A. Prints the contents of the current directory
  • B. Prints the path of the current working directory
  • C. Prints the current username
  • D. Prints the previous working directory
Answer

B. pwd stands for “print working directory” — it tells you where you currently are in the filesystem.

Q2. In a filesystem tree, what is the relationship between ~/Documents and ~?

  • A. They are siblings
  • B. ~ is a child of ~/Documents
  • C. ~/Documents is a child of ~
  • D. They are the same directory
Answer

C. ~/Documents lives inside ~, so ~ is the parent and ~/Documents is the child.

Q3. Which flag combination lists all files (including hidden ones) with human-readable sizes in reverse order?

  • A. ls -a
  • B. ls -lh
  • C. ls -lhra
  • D. ls -R
Answer

C. -l long form, -h human-readable sizes, -r reverse order, -a all files.

Q4. What does ~ expand to?

  • A. The root of the filesystem
  • B. The current working directory
  • C. Your home directory
  • D. The Desktop
Answer

C. ~ is a shortcut for the current user’s home directory, e.g., /Users/yourname.

Q5. You are in /Users/jsmith/Projects. Which of the following is a relative path?

  • A. /Users/jsmith/Projects/notes.txt
  • B. ~/notes.txt
  • C. ../notes.txt
  • D. /etc/hosts
Answer

C. Anything that doesn’t start with / (and isn’t ~, which expands to an absolute path) is relative. ../notes.txt refers to a file in the parent directory of wherever you currently are.

Q6. What does cd - do?

  • A. Goes to the home directory
  • B. Goes up one directory level
  • C. Returns to the previous directory you were in
  • D. Prints an error — - is not a valid path
Answer

C. cd - jumps back to the last directory you were in, making it easy to hop between two locations.

Q7. You want to create ~/Projects/computer-literacy but you’re not sure whether ~/Projects exists. What’s the safest single command?

  • A. mkdir ~/Projects/computer-literacy
  • B. mkdir -p ~/Projects/computer-literacy
  • C. touch ~/Projects/computer-literacy
  • D. cd ~/Projects/computer-literacy
Answer

B. The -p flag tells mkdir to also create any missing parent directories, so it will make ~/Projects for you if needed.

Q8. What does the Tab key do at the shell prompt?

  • A. Inserts four spaces
  • B. Autocompletes filenames and command names
  • C. Runs the current command
  • D. Switches to another open terminal window
Answer

B. Tab completion is the single biggest quality-of-life feature of the shell. If Tab won’t complete a name, that name probably doesn’t exist where you think it does.

Q9. Which command creates an empty file called hello.txt?

  • A. mkdir hello.txt
  • B. touch hello.txt
  • C. cat hello.txt
  • D. nano hello.txt (without saving)
Answer

B. touch creates an empty file if the file doesn’t already exist.

Q10. You have a file called draft.txt and want to rename it to final.txt. Which command works?

  • A. rename draft.txt final.txt
  • B. cp draft.txt final.txt
  • C. mv draft.txt final.txt
  • D. ln draft.txt final.txt
Answer

C. mv handles both moving and renaming — renaming is just moving from one path to another in the same directory.

Q11. What does the . refer to in mv drafts/readme.txt .?

  • A. The parent directory
  • B. The home directory
  • C. The current directory
  • D. A hidden file
Answer

C. A single dot always means “the current directory.” So this command moves drafts/readme.txt into wherever you are right now.

Q12. What does .. mean in a path?

  • A. The current directory
  • B. The home directory
  • C. The parent directory
  • D. The root of the filesystem
Answer

C. Two dots always mean “the parent directory.” cd .. moves up one level.

Q13. Which command correctly copies an entire folder called drafts to a new folder called drafts-backup?

  • A. cp drafts drafts-backup
  • B. cp -r drafts drafts-backup
  • C. mv drafts drafts-backup
  • D. touch drafts-backup
Answer

B. Copying a directory requires -r (recursive), because you’re copying the folder and everything inside it. Plain cp only works on individual files.

Q14. What is the biggest danger of rm?

  • A. It requires an internet connection
  • B. It’s slow on large files
  • C. It permanently deletes files with no Trash and no undo
  • D. It only works on files inside your home directory
Answer

C. rm bypasses the Trash entirely. There is no undo. Read every rm command twice.

Q15. In nano, which shortcut saves the file?

  • A. Cmd + S
  • B. Control + S
  • C. Control + O
  • D. Control + X
Answer

C. In nano, ^O (Control + O) writes the file — think “O for output.” ^X exits.

Q16. In nano’s on-screen help, what does the ^ symbol mean?

  • A. The Shift key
  • B. The Control key
  • C. The Option key
  • D. The up arrow
Answer

B. ^ is the traditional Unix shorthand for the Control key. So ^X means Control + X.

Q17. Why should you avoid running cat on a large CSV file?

  • A. It will corrupt the file
  • B. It will dump thousands of lines into your terminal all at once
  • C. cat doesn’t work on CSV files
  • D. It will require administrator privileges
Answer

B. cat prints the entire file to the terminal. For a big file that’s a flood of unreadable output. Use head, less, or wc -l instead.

Q18. You’re stuck inside less and want to get back to your normal prompt. What do you press?

  • A. Control + C
  • B. q
  • C. Escape
  • D. Control + X
Answer

B. In less (and in man pages, which use the same viewer), pressing q quits back to the shell.

Q19. What does wc -l data.csv report?

  • A. The number of words in the file
  • B. The number of characters in the file
  • C. The number of lines in the file
  • D. The file size in bytes
Answer

C. wc is “word count,” and the -l flag switches it to counting lines. Handy for quickly estimating how many rows are in a CSV (remember: subtract 1 for the header).

Q20. Which command downloads a file from a URL and saves it using the filename from that URL?

  • A. wget url
  • B. curl url
  • C. curl -O url
  • D. download url
Answer

C. Plain curl url prints the response to the terminal. The -O flag (capital O) tells curl to save the response as a file, using the name from the URL.

Q21. What is a CSV file?

  • A. A compressed archive of spreadsheets
  • B. A binary format for storing databases
  • C. A plain-text file where each row is a line and columns are separated by commas
  • D. A Microsoft Excel workbook
Answer

C. “CSV” = comma-separated values. It’s plain text, portable, and readable by virtually every data tool.

Q22. What does head -n 20 data.csv > sample.csv do?

  • A. Prints the first 20 lines to the terminal and to sample.csv
  • B. Appends the first 20 lines of data.csv to sample.csv
  • C. Writes the first 20 lines of data.csv into sample.csv, overwriting sample.csv if it exists
  • D. Renames data.csv to sample.csv
Answer

C. > is the redirection operator: send the output that would have printed into a file. It overwrites the target silently — no confirmation prompt.

Q23. What’s the difference between > and >>?

  • A. > prints to the screen; >> writes to a file
  • B. > overwrites the target file; >> appends to the target file
  • C. > works on files; >> works on directories
  • D. They are identical
Answer

B. Single > overwrites (silently!); double >> appends onto the end of an existing file (or creates it if it doesn’t exist).

Q24. Which command searches recursively for the text TODO starting from the current directory, showing line numbers?

  • A. grep TODO
  • B. grep -n TODO
  • C. grep -r TODO
  • D. grep -rn TODO .
Answer

D. -r recursive, -n line numbers, . = start from the current directory. Together these are how you find every leftover TODO in a project.

Q25. Which grep flag makes the search case-insensitive?

  • A. -c
  • B. -i
  • C. -v
  • D. -x
Answer

B. -i makes the pattern case-insensitive, so grep -i todo matches TODO, Todo, and todo.

Q26. Why would you ever want two terminal windows open at the same time?

  • A. To run commands faster in parallel (at the same time)
  • B. Because some commands (like a local web server) take over the prompt, so you need a second shell for other work
  • C. Because macOS requires it
  • D. To share files between windows
Answer

B. Long-running processes — web servers, quarto preview, jupyter lab, less, nano — keep the first terminal busy. A second window gives you a place to keep working.

Q27. What is localhost?

  • A. A public web server you can share with others
  • B. A special name that always refers to your own computer
  • C. The name of the terminal application
  • D. Another word for ~
Answer

B. localhost (a.k.a. 127.0.0.1) means “this same machine.” A server running at localhost:8000 is only reachable from your own computer.

Q28. You’re running python3 -m http.server 8000 and want to stop it. What do you press?

  • A. q
  • B. Control + X
  • C. Control + C
  • D. Escape
Answer

C. Control + C sends an “interrupt” signal — the universal “please stop, program” keystroke for most running commands.

Q29. Classic Jupyter Notebook and JupyterLab open which file extension?

  • A. .qmd
  • B. .py
  • C. .ipynb
  • D. .html
Answer

C. Both tools use the same .ipynb notebook file format — JupyterLab is essentially a more modern editor for the same files.

Q30. Why is it easier to see what changed between two versions of a .qmd file than between two versions of a .ipynb file?

  • A. Because Quarto is newer software.
  • B. Because .qmd files are plain text (Markdown), while .ipynb files are stored as JSON.
  • C. Because Quarto files are always smaller.
  • D. Because macOS has a special mode for Quarto.
Answer

B. A .qmd file is Markdown — ordinary readable text with code fences. Comparing two versions produces a clear, line-by-line report of what changed. A .ipynb file is a JSON document that also stores hidden information about each cell and each run, so even a small visible change on screen can cause many invisible changes in the file, making the comparison noisy and hard to read.
